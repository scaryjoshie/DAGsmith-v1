# Codebase Audit — April 2026

Read-only pass across `frontend/src/` and `dagsmith/`. No changes made.

---

## HIGH

### 1. Duplicate `getFlow` fetches for the same flow in App.tsx

`frontend/src/App.tsx` fetches the same flow up to **four times** for a single user action:

- `selectedFlow` (lines 89-100): fetched when `selectedNode` changes, passed to Inspector
- `activeFlowView` (lines 111-120): fetched when `activeFlow` (active panel) changes, passed to sidebar + preflight
- `refetchSelectedFlow` (line 244): manual refetch for Inspector mutations
- `handleFlowMutatedWithView` (lines 121-131): refetches `activeFlowView` on mutation

When a node is selected in the active panel, both `selectedFlow` and `activeFlowView` fetch the same flow from the same backend endpoint within milliseconds of each other. The two states represent the same data (the active flow's `FlowView`) but carry different names and are refreshed independently. Inspector gets `selectedFlow`; preflight modal and sidebar diagnostics get `activeFlowView`.

**Fix direction**: Collapse into a single `flowView` state. When `selectedNode` is set, it must be in the active flow anyway — `activeFlowView` already has the data.

---

### 2. No tests for PATCH /nodes (rename, ref, input, exits, rename_exits)

The `PATCH /api/workspaces/{name}/flows/{flow_id}/nodes/{node_name}` endpoint was added in the A4–A6 sprint and is the most mutation-rich handler in the codebase. It handles five distinct code paths (rename, ref update, input update, exit rename with edge cascade, exit reconciliation with edge cascade). None of these paths are covered in `tests/test_server.py`. The only relevant test is `test_second_edge_on_same_exit_allowed` (line 111), which predates this endpoint.

**Fix direction**: Add a `TestUpdateNode` class in `test_server.py` with at minimum: rename happy path, rename to existing name (400), invalid identifier (400), exit rename cascade, exit removal cascade.

---

### 3. Test leftover stub files in the customer example

`examples/customer/onboarding/` contains at least 9 stub Python files created during manual testing sessions (`test_node.py`, `test_node2.py`, `my_new_node.py`, `zoom_test_node.py`, `real_zoom_test.py`, `test_b4_node.py`, `my_test_b4_node.py`, `test_node_t1c.py`, `test_fitview_node.py`, `test2.py`). None are referenced in `flow.json`. They are orphaned stubs that pollute the example workspace, appear in file listings, and will confuse new contributors or users evaluating the tool.

**Fix direction**: Delete all of them. Check that `flow.json` references only the canonical nodes.

## MEDIUM

### 4. Dead component: `NodePanel.tsx`

`frontend/src/components/NodePanel.tsx` (~200 lines) is not imported anywhere in the current codebase. It was a predecessor to the Inspector panel. It defines its own `shortName` helper (line 187) and references `NodePanel.module.css`. Both files are dead weight.

**Fix direction**: Delete `NodePanel.tsx` and `NodePanel.module.css`.

### 5. Three copies of `shortName`

`shortName(typeRef: string): string` — extracts the last dotted segment — is copy-pasted in:
- `frontend/src/components/Inspector.tsx:7`
- `frontend/src/components/NodePanel.tsx:187` (dead, see #4)
- `frontend/src/components/RunPanel.tsx:89`

If `NodePanel` is deleted that leaves two. Should live in a shared `src/utils.ts`.

### 6. Shell's `sidebarHeader` and `sidebarFooter` slots are never passed

`frontend/src/components/Shell.tsx:5-7` declares optional `sidebarHeader` and `sidebarFooter` props. `App.tsx` never passes either — the sidebar header ("DAGsmith") and footer (Run/Add buttons) are rendered inside `LeftSidebar`, not via Shell slots. The slots exist as dead API surface, and the fallback `<div className={styles.sidebarHeader}>DAGsmith</div>` inside Shell is also never reached.

**Fix direction**: Remove the two slot props and the fallback rendering from Shell; they add confusion without use.

### 7. CLAUDE.md describes a state that no longer exists

`CLAUDE.md` line 32: `"dockview migration (attempted, rolled back)"` — dockview is now the live tab system; the migration was *not* rolled back. The entire "Deliberately NOT at this state" block (lines 29-35) describes the pre-dockview history and is actively misleading for new contributors. The "Known limitations" section also describes the pre-dockview split behavior.

**Fix direction**: Rewrite the frontend state section to describe the actual current state.

### 8. `eslint-disable` on `react-hooks/exhaustive-deps` in DockviewCanvas

`frontend/src/components/DockviewCanvas.tsx:159,178`: two `// eslint-disable-next-line react-hooks/exhaustive-deps` suppressions. These suppress legitimate stale-closure warnings. The `onReady` callback captures `workspaceName` at mount time but the workspace-change effect handles updates via `workspaceNameRef`. The suppression is technically correct but the intent is non-obvious. A comment explaining the invariant would help; alternatively, the ref approach could be made explicit with a rename.

## LOW

### 9. `react-icons` is listed in `package.json` but has no consumer

`frontend/package.json` includes `"react-icons": "^5.6.0"`. Grep finds zero imports of `react-icons` anywhere in `frontend/src/`. The brand icons (Python logo, flow glyph) use a local `src/icons/BrandIcons.tsx`. This dep can be removed.

### 10. `onFlowRefetch` callback is redundant with `onFlowMutated`

`InspectorProps` carries two separate refresh callbacks: `onFlowMutated` (from `SelectionContext`) and `onFlowRefetch` (prop from App). Both are called after mutations. `onFlowMutated` triggers the canvas refresh; `onFlowRefetch` triggers `selectedFlow` refresh in App. With the fix from finding #1 (collapse `selectedFlow`/`activeFlowView`), `onFlowRefetch` disappears entirely.

### 11. `idempotent addEdge` has no test

T1-j (commit `c69f5b6`) added duplicate-edge detection to `POST /edges`. The behavior is correct but untested. Should be a 2-line test: POST the same edge twice, assert the second response equals the first and `flow.edges` count hasn't increased.

### 12. `handleNodeRenamed` in App.tsx duplicates a `getFlow` call

`frontend/src/App.tsx:251-260`: `handleNodeRenamed` updates `selectedNode.nodeId` then immediately calls `getFlow` — but the same call is already triggered by the `useEffect` at line 89-100 that watches `selectedNode`. The explicit `getFlow` call in `handleNodeRenamed` fires first, then the effect fires again ~1 render later, causing a redundant fetch.
